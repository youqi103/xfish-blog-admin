## 问题分析

1. **后端返回数据格式**：

   ```json
   {
     "records": [...],
     "total": 0,
     "size": 10,
     "current": 1,
     ...
   }
   ```

2. **前端期望数据格式**：

   ```json
   {
     "code": 0,
     "data": {
       "records": [...],
       "total": 0,
       ...
     },
     "message": "success"
   }
   ```

3. **问题根源**：

   * 代码中 `searchUser` 函数期望返回 `BaseResponse` 类型数据（包含 `code`、`data`、`message` 字段）

   * 但实际后端直接返回了包含 `records` 字段的数据对象

   * 导致 `userList.data` 为 `undefined`，进入错误处理分支，返回空数据

## 修复方案

修改 `src/pages/Admin/UserManage/index.tsx` 中的数据处理逻辑，使其能同时兼容两种数据格式：

1. 检查返回数据是否直接包含 `records` 字段
2. 如果是，直接使用该数据作为响应数据
3. 否则，使用 `data` 字段中的数据
4. 确保 `total` 字段正确设置，避免表格显示异常

## 具体修改点

在 `request` 回调函数中，修改数据提取逻辑：

* 从第137行开始的 `userList` 数据处理部分

* 添加对直接返回 `records` 字段的兼容处理

* 确保 `total` 字段使用实际数据长度，避免后端返回 `total: 0` 导致的问题

## 预期效果

* 表格能正确显示后端返回的用户数据

* 支持两种数据格式：直接返回包含 `records` 的对象，或包含在 `data` 字段中的对象

* 分页功能正常工作

* 表格显示正确的总条数
